### 发现及已实施修复

1. **客户端无条件 30 秒超时。** `acomplete` 原先 `min(30, timeout)`，使 180 秒任务预算
   无法用于较慢的一次生成。现在使用执行器传入的剩余时间，外层仍限制活跃总时长；
   不增加隐藏重试。真实超时的服务端细节未知，不能据此承诺改完必然成功。
2. **检索诊断挤占模型上下文。** 每条结果包含多种距离、排名、分数、哈希等诊断信息，
   多次检索反复发送。现给模型的观察保留原文、source_id、document/chunk ID 和定位；
   完整诊断仍留在 trace，正文哈希仍在 evidence registry，未放宽上下文上限。
3. **输出终止信号缺失。** 现在记录 `finish_reason`；`length` 记预算终止，空响应记失败，
   不再以“资料不足”替代空响应并标记成功。
4. **B0 没有可读检索轨迹。** 增加调用、观察、失败原因和耗时保存；B0 也检查实际用量
   是否超总 token 上限，保留强单步基线，不引入额外检索循环。
5. **真实重排协议。** 改用 `top_n`，保留 `relevance_score`，拒绝缺失/非有限分数、
   重复/越界索引和错误结果条数，使无效结果走现有显式降级路径。
6. **评测证据完整性。** 冻结完整预算和评测器哈希；校验实际模型/向量后端/提供方；
   缺少报告即不成功；未知请求用量保留预留额；未实际启动的预算阻塞样本不污染延迟。

四个 context_tokens 失败样本在**不发真实模型请求**的回放中，从
24,911 / 28,559 / 27,222 / 27,117 降为 17,039 / 20,687 / 23,028 / 22,994，
均低于原 24,000 上限，工具调用配对相同。此结果仅证明该处预算拦截得到缓解，
不等于后续生成或报告已成功。冻结 v1 原始结果与源码保留，修复后工作区属于下一版本。
